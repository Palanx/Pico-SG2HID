# Phase 22-scaffold-typecheck-transitive — a real typecheck gate, and transitive includes in the boundary sweep

## Goal

Two gates that report a pass today without checking what their names say. After this phase:

| # | gate | today (measured 2026-09-29) | after this phase |
|---|---|---|---|
| 1 | `scripts/check.sh typecheck` | prints `workflow gap: no 'typecheck' tool configured`, runs nothing, exits 0 | prints `== typecheck: make typecheck` and `PASS`, no `workflow gap` line, exits 0 |
| 2 | `make typecheck` | `No rule to make target` | compiles each `src/core/*.h` on its own; a header that uses a type without including the header that declares it makes `make typecheck` exit non-zero, naming that header |
| 3 | `tests/test_boundaries.sh` on a tree where `src/core/x.cpp` includes `common/y.h` and `src/common/y.h` includes `hal/bus.h` | `sweep( )` returns 0: `.claude/hooks/boundary-check.sh` passes both files | `sweep( )` returns 1, and `run_all( )` prints `FAIL: R-ARCH-02: forbidden dependency direction` followed by `.claude/hooks/include-check.sh`'s chain |

`make typecheck` compiles, for each header `H` in `src/core/*.h`, a one-line translation unit
`#include "H"` read from stdin, with `$(CXX) $(CXXFLAGS) -fsyntax-only -xc++ -`. It does **not**
pass the header itself as the main file (the form written in the PHASES.md row and in the
tech-debt entry): measured 2026-09-29 with Apple clang 21, that form fails five of the six
current headers with `-Wpragma-once-outside-header` and `-Wunused-const-variable` under
`-Werror`, which are artefacts of compiling a header as a main file, not missing includes. The
include form passes all six current headers and fails a header that uses `std::uint8_t`
without `<cstdint>` (`use of undeclared identifier 'std'`), also measured the same day.

`sweep( )` hands every file under `src/` to both hooks, in the same loop, under the same exit
contract: 0 clean, 2 a layering breach, anything else "the hook did not run". Both hooks
already honour that contract (read their `Exit codes` comments). The include hook is
overridable as `INCLUDE_HOOK`, as the boundary hook already is as `HOOK`. R-ARCH-02's scope
clause in `docs/constraints.md` stops naming the transitive include as a miss in the same edit.

`make test` still needs only a C++23 compiler and `python3`; `make typecheck` is not added to
`make test`. Every existing result line of `tests/test_boundaries.sh` keeps its prefix and
wording, except the `rejection cases:` floor line, whose number rises.

## Plan

1. **Add `make typecheck`** — touches `Makefile`. Add `CORE_HDRS := $(wildcard src/core/*.h)`
   beside `CORE_SRC`; add `typecheck` to `.PHONY` and to the header comment ("compiles each
   `src/core/*.h` on its own; needs only the host C++ compiler"). The recipe loops over
   `$(CORE_HDRS)`, pipes `printf '#include "%s"\n' "$$h"` into
   `$(CXX) $(CXXFLAGS) -fsyntax-only -xc++ -`, runs every header even after a failure, prints
   `typecheck: <header> does not compile on its own` for each failing header, and exits
   non-zero if any failed. `CORE_HDRS` stays a plain make variable so the command line can
   override it (step 2's check and the acceptance criteria rely on that).
   Check: `make typecheck` → exit 0, no `does not compile` line.
2. **Prove it rejects** — no file change. Check (both from the repo root):
   `d=$( mktemp -d ) && printf '#pragma once\ninline std::uint8_t f( ) { return 0; }\n' > "$d/bad.h" && make typecheck CORE_HDRS="$d/bad.h"; echo "rc=$?"; rm -rf "$d"`
   → an `undeclared identifier 'std'` error, a `does not compile on its own` line naming
   `bad.h`, and `rc=` non-zero; the same with `#include <cstdint>` added as the second line →
   `rc=0`.
3. **Register the gate** — touches `.claude/workflow/toolchain.manual.json`: add
   `"typecheck": "make typecheck"` to `commands`. Check: `scripts/check.sh typecheck` → prints
   `== typecheck: make typecheck` and `PASS`, no `workflow gap` line, exit 0.
4. **Sweep with both hooks, and rewrite R-ARCH-02's clause in the same edit** — touches
   `tests/test_boundaries.sh` and `docs/constraints.md`.
   - `tests/test_boundaries.sh`: add `INCLUDE_HOOK="${INCLUDE_HOOK:-$ROOT/.claude/hooks/include-check.sh}"`
     beside `HOOK`, with the same kind of comment. The executable check before `run_all "$ROOT"`
     covers both hooks. Inside `sweep( )`'s loop, run each of `"$HOOK"` and `"$INCLUDE_HOOK"`
     on the path exactly as `"$HOOK"` is run today (same `CLAUDE_PROJECT_DIR`, `</dev/null`,
     `2>&1`) and feed each exit code through the same `case`; the "hook exited N" line names
     which hook. Update the file's header comment and `sweep( )`'s comment to say both hooks
     run.
   - Add two rejection cases after the existing three, each counted in `rejected`, each result
     line containing `rejection case`:
     (a) the tree from Goal row 3 (`boundaries.rules` copied in, `src/core/x.cpp` =
     `#include "common/y.h"`, `src/common/y.h` = `#include "hal/bus.h"`): `sweep` must return
     exactly 1;
     (b) a clean tree with `INCLUDE_HOOK` pointed at a stub that exits 3: `sweep` must
     return exactly 2.
     Raise the floor from 3 to 5 in both places the number appears.
   - `docs/constraints.md`, R-ARCH-02: the scope clause names both hooks as the check. Delete
     the sentence part that lists the transitive include (`src/core/x.cpp` → `common/y.h` →
     `hal/bus.h`) as outside the binding. The remaining misses stay (macro `#define`d in
     another header; newline in a name; symlinked layer directory; conditionals other than
     `#if 0`), and the "file in no declared layer" miss is restated to what is true now: such
     a file is judged only through a layered file that includes it (`include-check.sh`'s
     reverse lookup by basename, per its header comment); one that no layered file includes is not judged. Add: `include-check.sh`
     needs bash >= 4 (`local -A`); under macOS `/bin/bash` 3.2 it exits 0 on the Goal row 3
     tree (measured 2026-09-29), in which case rejection case (a) fails `make test` instead of
     the sweep passing silently. Name the fixture without the literal `common/y.h` path — an
   acceptance criterion greps the file for it.
   Check: `sh tests/test_boundaries.sh` → exit 0, five `ok:` lines containing
   `rejection case`, `ok:   rejection cases: 5/5`; `python3 tests/test_rule_traceability.py`
   → exit 0; `grep -c 'common/y.h' docs/constraints.md` → 0.
5. **Prove the new cases are live** — no file change. Check:
   `INCLUDE_HOOK=/usr/bin/true sh tests/test_boundaries.sh; echo "rc=$?"` → a `FAIL:` line for
   rejection case (a) and `rc=1` (case (b) sets its own `INCLUDE_HOOK`, so it still passes).
6. **Write the operator's verification** — touches `docs/phases/22-scaffold-typecheck-transitive/verify.md`
   (R-PROC-02): what the two gates check, for a non-specialist (what "a header compiles on its
   own" means, what a transitive include is, using the Goal row 3 chain), and the commands
   from the Acceptance criteria below with what each should print.
   Check: `sh tests/test_phase_docs.sh` → exit 0.

## Acceptance criteria

```
make typecheck                                                   # expect: exit 0, no "does not compile" line
d=$( mktemp -d ) && printf '#pragma once\ninline std::uint8_t f( ) { return 0; }\n' > "$d/bad.h" && make typecheck CORE_HDRS="$d/bad.h"; echo "rc=$?"; rm -rf "$d"
                                                                 # expect: "undeclared identifier 'std'", a "does not compile on its own" line naming bad.h, rc= non-zero
d=$( mktemp -d ) && printf '#pragma once\n#include <cstdint>\ninline std::uint8_t f( ) { return 0; }\n' > "$d/good.h" && make typecheck CORE_HDRS="$d/good.h"; echo "rc=$?"; rm -rf "$d"
                                                                 # expect: rc=0
scripts/check.sh typecheck                                       # expect: "== typecheck: make typecheck", "PASS", no "workflow gap" line, exit 0
sh tests/test_boundaries.sh                                      # expect: exit 0, "ok:   rejection cases: 5/5", an ok line for the transitive-include rejection case
INCLUDE_HOOK=/usr/bin/true sh tests/test_boundaries.sh; echo "rc=$?"
                                                                 # expect: FAIL line for the transitive-include rejection case, rc=1
grep -c 'common/y.h' docs/constraints.md                         # expect: 0
grep -n 'include-check.sh' docs/constraints.md                   # expect: at least one hit, on the R-ARCH-02 line
python3 tests/test_rule_traceability.py                          # expect: exit 0
make test                                                        # expect: exit 0, last line "OK"
make lint                                                        # expect: exit 0
make -n test | grep -c 'fsyntax-only'                           # expect: 0 — make test does not run the typecheck; its toolchain needs are unchanged
```
